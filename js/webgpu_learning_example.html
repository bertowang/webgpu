一、WebGPU 数据处理流程

一帧画面从 CPU 侧的 JavaScript 数据，到 GPU 绘制并呈现到画布，依次经过以下节点。每个节点说明对应 API 与设计原因。

1
CPU · JS准备源数据
构造顶点数组（每个顶点 6 个 float：位置 xyz + 颜色 rgb）、索引数组（36 个 uint16），并在每帧计算 MVP 矩阵。
为什么：GPU 只读取缓冲区里的二进制数据，JS 必须先按 GPU 能理解的布局把数据排好，再交给 GPU。
↓
2
CPU · JS创建 GPUBuffer 并上传
device.createBuffer({ size, usage, mappedAtCreation })；用 getMappedRange() 写入静态顶点/索引，用 queue.writeBuffer() 每帧更新 Uniform。
为什么：usage 必须在创建时声明（VERTEX / INDEX / UNIFORM / COPY_DST）且不可更改，驱动据此决定内存放置与访问权限；mappedAtCreation 让静态数据一次写入，省去额外拷贝命令。
↓
3
CPU · JS编译 WGSL 着色器
device.createShaderModule({ code }) 编译 WGSL；入口点为 @vertex vertex_main 与 @fragment fragment_main。
为什么：着色器在 GPU 上大规模并行执行。@location(0/1) 与顶点属性一一对应，@builtin(position) 是内建输出；编译错误通过 getCompilationInfo() 异步返回，不会同步抛异常。
↓
4
CPU · JS绑定资源（BindGroup）
由 pipeline.getBindGroupLayout(0) 取得布局，再用 createBindGroup() 把 uniform buffer 绑定到 @group(0) @binding(0)。
为什么：var<uniform> 是着色器里的“插槽”，BindGroup 填入真实资源。这层间接让同一管线可切换不同资源而不必重建管线。
↓
5
CPU · JS创建渲染管线（RenderPipeline）
createRenderPipeline({ layout, vertex, fragment, primitive, depthStencil }) 固化顶点布局、图元拓扑与深度状态。
为什么：管线是不可变对象，创建时做严格验证，渲染时几乎零开销，因此只创建一次、每帧复用。
↓
6
CPU · JS编码渲染命令
createCommandEncoder() → beginRenderPass() → setPipeline / setBindGroup / setVertexBuffer / setIndexBuffer / drawIndexed → pass.end()。
为什么：WebGPU 是显式 API，先记录整帧操作再提交。drawIndexed(36) 用 24 个顶点画出 12 个三角形，索引复用节省顶点内存。
↓
7
GPU提交到队列
device.queue.submit([encoder.finish()]) 把命令缓冲交给 GPU 队列顺序执行。
为什么：批量提交减少 CPU↔GPU 往返；CPU 无需等待 GPU 完成即可继续准备下一帧。
↓
8
GPU呈现到画布
context.getCurrentTexture() 取得当前交换链纹理作为颜色附件，GPU 完成后由浏览器合成显示。
为什么：每帧纹理由系统分配；canvas.width/height 变化时必须同步重建深度纹理，否则颜色与深度附件尺寸不匹配会验证失败。
01

mat4Multiply(a, b)

矩阵运算
矩阵乘法函数

该函数用于将两个 4×4 矩阵相乘，结果存储在新的 Float32Array 中。

  • 参数 a、b：均包含 16 个元素，表示两个 4×4 矩阵。
  • 返回值：新的 Float32Array，表示相乘后的结果矩阵。
查看函数代码
function mat4Multiply(a, b) {
    const result = new Float32Array(16);
    for (let i = 0; i < 4; i++) {
        for (let j = 0; j < 4; j++) {
            let sum = 0;
            for (let k = 0; k < 4; k++) {
                sum += a[i + k * 4] * b[k + j * 4];
            }
            result[i + j * 4] = sum;
        }
    }
    return result;
}
02

mat4RotationX(angle)

矩阵运算
X 轴旋转矩阵函数

该函数用于创建绕 X 轴旋转指定角度的 4×4 变换矩阵。

  • 参数 angle：旋转角度（弧度）。
  • 返回值：包含 16 个元素的 Float32Array，表示旋转矩阵。
查看函数代码
function mat4RotationX(angle) {
    const c = Math.cos(angle);
    const s = Math.sin(angle);
    return new Float32Array([
        1, 0, 0, 0,
        0, c, -s, 0,
        0, s, c, 0,
        0, 0, 0, 1
    ]);
}

04

mat4Perspective(fovy, aspect, near, far)

投影
透视投影矩阵函数

该函数用于创建透视投影变换矩阵，将 3D 坐标转换为裁剪坐标。

  • fovy：视野垂直角度（弧度）。
  • aspect：视口宽高比。
  • near / far：近平面 / 远平面距离。
  • 返回值：包含 16 个元素的 Float32Array，表示透视投影矩阵。
查看函数代码
function mat4Perspective(fovy, aspect, near, far) {
    const f = 1.0 / Math.tan(fovy / 2);
    return new Float32Array([
        f / aspect, 0, 0, 0,
        0, f, 0, 0,
        0, 0, (far + near) / (near - far), -1,
        0, 0, (2 * far * near) / (near - far), 0
    ]);
}
05

mat4LookAt(eye, target, up)

视图
视角矩阵函数（LookAt 变换）

该函数用于创建从观察者位置到目标点的视角变换矩阵。

  • eye：观察者位置坐标 [x, y, z]。
  • target：目标点坐标 [x, y, z]。
  • up：上方向向量 [x, y, z]，用于定义观察者的朝向。
  • 返回值：包含 16 个元素的 Float32Array，表示视角变换矩阵。
查看函数代码
function mat4LookAt(eye, target, up) {
    const zAxis = normalize(subtract(eye, target));
    const xAxis = normalize(cross(up, zAxis));
    const yAxis = cross(zAxis, xAxis);
    return new Float32Array([
        xAxis[0], yAxis[0], zAxis[0], 0,
        xAxis[1], yAxis[1], zAxis[1], 0,
        xAxis[2], yAxis[2], zAxis[2], 0,
        -dot(xAxis, eye), -dot(yAxis, eye), -dot(zAxis, eye), 1
    ]);
}

cross(a, b)

向量运算
向量叉积

返回两个三维向量的叉积，结果仍为一个三维向量。

查看函数代码
function cross(a, b) {
    return [
        a[1] * b[2] - a[2] * b[1],
        a[2] * b[0] - a[0] * b[2],
        a[0] * b[1] - a[1] * b[0]
    ];
}

normalize(v)

向量运算
向量归一化

将三维向量除以其长度，返回单位向量。

查看函数代码
function normalize(v) {
    const length = Math.sqrt(v[0] * v[0] + v[1] * v[1] + v[2] * v[2]);
    return [v[0] / length, v[1] / length, v[2] / length];
}
10

initWebGPU()

主流程
初始化 WebGPU

请求适配器与设备、配置 canvas 上下文、创建着色器模块与渲染管线、构建立方体顶点/索引/Uniform 缓冲、创建深度纹理，并启动渲染循环。

  • pushFace：立方体顶点数据，按面写入 4 个顶点（位置 + 颜色）。
  • ensureDepthTexture：按画布尺寸创建或重建深度纹理。
  • render：每帧更新 MVP 矩阵并写入 Uniform，执行渲染 pass 后请求下一帧。
  • resizeCanvas：让绘图缓冲区尺寸匹配 CSS 显示尺寸。
查看函数代码
async function initWebGPU() {
    const canvas = document.getElementById('webgpu-canvas');
    const adapter = await navigator.gpu.requestAdapter();
    if (!adapter) {
        throw new Error('No WebGPU adapter found');
    }

    const device = await adapter.requestDevice();
    const context = canvas.getContext('webgpu');
    const format = navigator.gpu.getPreferredCanvasFormat();
    context.configure({
        device: device,
        format: format,
        alphaMode: 'opaque'
    });

    const shaderModule = device.createShaderModule({
        code: `
            struct Uniforms {
                mvp: mat4x4f
            };

            @group(0) @binding(0)
            var<uniform> uniforms: Uniforms;

            struct VertexOutput {
                @builtin(position) position : vec4f,
                @location(0) color : vec4f
            };

            @vertex
            fn vertex_main(@location(0) position : vec3f, @location(1) color : vec3f) -> VertexOutput {
                var output: VertexOutput;
                output.position = uniforms.mvp * vec4f(position, 1.0);
                output.color = vec4f(color, 1.0);
                return output;
            }

            @fragment
            fn fragment_main(input : VertexOutput) -> @location(0) vec4f {
                return input.color;
            }
        `
    });

    const pipeline = device.createRenderPipeline({
        layout: 'auto',
        vertex: {
            module: shaderModule,
            entryPoint: 'vertex_main',
            buffers: [{
                arrayStride: 6 * 4,
                attributes: [
                    { shaderLocation: 0, offset: 0, format: 'float32x3' },
                    { shaderLocation: 1, offset: 3 * 4, format: 'float32x3' }
                ]
            }]
        },
        fragment: {
            module: shaderModule,
            entryPoint: 'fragment_main',
            targets: [{ format }]
        },
        primitive: { topology: 'triangle-list', cullMode: 'none' },
        depthStencil: {
            format: 'depth24plus',
            depthWriteEnabled: true,
            depthCompare: 'less'
        }
    });

    const vertices = [];
    const pushFace = (a, b, c, d, color) => {
        for (const p of [a, b, c, d]) vertices.push(...p, ...color);
    };

    // 立方体顶点数据
    pushFace([-0.5,-0.5, 0.5], [ 0.5,-0.5, 0.5], [ 0.5, 0.5, 0.5], [-0.5, 0.5, 0.5], [1.0, 0.3, 0.3]);
    pushFace([ 0.5,-0.5,-0.5], [-0.5,-0.5,-0.5], [-0.5, 0.5,-0.5], [ 0.5, 0.5,-0.5], [0.3, 0.8, 0.3]);
    pushFace([ 0.5,-0.5, 0.5], [ 0.5,-0.5,-0.5], [ 0.5, 0.5,-0.5], [ 0.5, 0.5, 0.5], [0.3, 0.5, 1.0]);
    pushFace([-0.5,-0.5,-0.5], [-0.5,-0.5, 0.5], [-0.5, 0.5, 0.5], [-0.5, 0.5,-0.5], [1.0, 0.85, 0.2]);
    pushFace([-0.5,-0.5,-0.5], [ 0.5,-0.5,-0.5], [ 0.5,-0.5, 0.5], [-0.5,-0.5, 0.5], [1.0, 0.2, 1.0]);
    pushFace([-0.5, 0.5,-0.5], [ 0.5, 0.5,-0.5], [ 0.5, 0.5, 0.5], [-0.5, 0.5, 0.5], [0.2, 1.0, 1.0]);

    const vertexData = new Float32Array(vertices);
    const indices = new Uint16Array([
        0,  1,  2,   0,  2,  3,
        4,  5,  6,   4,  6,  7,
        8,  9, 10,   8, 10, 11,
        12, 13, 14,  12, 14, 15,
        16, 17, 18,  16, 18, 19,
        20, 21, 22,  20, 22, 23
    ]);

    const vertexBuffer = device.createBuffer({
        size: vertexData.byteLength,
        usage: GPUBufferUsage.VERTEX | GPUBufferUsage.COPY_DST,
        mappedAtCreation: true
    });
    new Float32Array(vertexBuffer.getMappedRange()).set(vertexData);
    vertexBuffer.unmap();

    const indexBuffer = device.createBuffer({
        size: indices.byteLength,
        usage: GPUBufferUsage.INDEX | GPUBufferUsage.COPY_DST,
        mappedAtCreation: true
    });
    new Uint16Array(indexBuffer.getMappedRange()).set(indices);
    indexBuffer.unmap();

    const uniformBuffer = device.createBuffer({
        size: 64,
        usage: GPUBufferUsage.UNIFORM | GPUBufferUsage.COPY_DST
    });

    const bindGroup = device.createBindGroup({
        layout: pipeline.getBindGroupLayout(0),
        entries: [{ binding: 0, resource: { buffer: uniformBuffer } }]
    });

    let depthTexture = null;
    function ensureDepthTexture() {
        if (depthTexture && depthTexture.width === canvas.width && depthTexture.height === canvas.height) return;
        if (depthTexture) depthTexture.destroy();
        depthTexture = device.createTexture({
            size: [canvas.width, canvas.height],
            format: 'depth24plus',
            usage: GPUTextureUsage.RENDER_ATTACHMENT
        });
    }
    ensureDepthTexture();

    let rotation = 0;
    function render() {
        resizeCanvas();
        ensureDepthTexture();
        rotation += 0.01;

        const projection = mat4Perspective(Math.PI / 4, canvas.width / canvas.height, 0.1, 100);
        const view = mat4LookAt([0, 0, 3], [0, 0, 0], [0, 1, 0]);
        const model = mat4Multiply(mat4RotationY(rotation), mat4RotationX(rotation * 0.6));
        const mvp = mat4Multiply(mat4Multiply(projection, view), model);
        device.queue.writeBuffer(uniformBuffer, 0, mvp);

        const encoder = device.createCommandEncoder();
        const pass = encoder.beginRenderPass({
            colorAttachments: [{
                view: context.getCurrentTexture().createView(),
                clearValue: { r: 0.05, g: 0.06, b: 0.09, a: 1 },
                loadOp: 'clear',
                storeOp: 'store'
            }],
            depthStencilAttachment: {
                view: depthTexture.createView(),
                depthClearValue: 1.0,
                depthLoadOp: 'clear',
                depthStoreOp: 'store'
            }
        });
        pass.setPipeline(pipeline);
        pass.setBindGroup(0, bindGroup);
        pass.setVertexBuffer(0, vertexBuffer);
        pass.setIndexBuffer(indexBuffer, 'uint16');
        pass.drawIndexed(indices.length);
        pass.end();
        device.queue.submit([encoder.finish()]);
        requestAnimationFrame(render);
    }

    function resizeCanvas() {
        const displayWidth = canvas.clientWidth;
        const displayHeight = canvas.clientHeight;

        if (canvas.width !== displayWidth || canvas.height !== displayHeight) {
            canvas.width = displayWidth;
            canvas.height = displayHeight;
        }
    }

    // 开始渲染循环
    requestAnimationFrame(render);
}

二、底层原理与 API 设计动机

WebGPU 是显式图形 API：它把驱动原本隐式完成的工作交给开发者声明。下面解释本例每个关键 API 为什么存在，以及它背后的运行机制。

1. 为什么分 Adapter 与 Device

requestAdapter() 挑选物理 GPU（或软件回退实现），requestDevice() 创建逻辑设备，后者是后续所有资源的工厂。

适配器代表硬件能力（features / limits），设备代表资源隔离域。分开后可以针对不同硬件选择特性，且不同 Device 之间的资源不共享，生命周期更清晰。

2. Canvas 配置与像素格式

canvas.getContext('webgpu') 得到的是交换链抽象；context.configure({ device, format, alphaMode }) 告诉浏览器用哪个设备渲染、像素格式以及透明处理方式。

  • getPreferredCanvasFormat() 返回平台偏好格式（通常为 bgra8unorm），避免通道顺序转换开销。
  • alphaMode:'opaque' 表示画布不透明，合成阶段更快。

3. WGSL 的编译模型

createShaderModule({ code }) 只编译、不链接；错误通过 getCompilationInfo() 异步返回，所以页面里用非阻塞方式检查。

WGSL 是类型安全、可静态验证的语言，禁止未定义行为，浏览器能在提交前验证着色器。@vertex / @fragment 标记入口点，@location 与顶点属性匹配，var<uniform> 表示所有顶点共享的只读数据。

4. Buffer 的 usage 标志与上传策略

GPUBufferUsage.VERTEX | COPY_DST 这类组合在 createBuffer() 时一次性声明。

  • usage 不可更改：驱动据此决定内存放置与访问权限，例如 VERTEX 表示可被顶点阶段读取，COPY_DST 表示可被写入。
  • mappedAtCreation:true 在创建时直接映射内存写入静态数据（顶点、索引），省去额外的 copyBufferToBuffer 命令。
  • 每帧变化的 MVP 矩阵用 queue.writeBuffer() 更新同一个 Uniform Buffer：buffer 对象不变，只改内容。
  • Uniform Buffer 大小 64 字节 = mat4x4f（16 个 f32 × 4 字节）；WebGPU 要求绑定偏移按 256 字节对齐，本例 offset 为 0、size 为 64 是合法的。

5. BindGroup 与布局解耦

layout:'auto' 让管线从 WGSL 声明自动推导绑定布局；getBindGroupLayout(0) 取出第 0 组布局，再创建 BindGroup 填入具体 buffer。

@group(0) @binding(0) 是着色器里的“插槽号”，BindGroup 负责填入真实资源。这层间接让同一管线可以绑定不同资源，切换时只需传入不同的 BindGroup。

6. 为什么 RenderPipeline 不可变

管线把着色器、顶点格式、图元拓扑和深度状态固化为一个对象；创建成本高（编译 + 验证），渲染时开销极低。

  • arrayStride: 6 * 4 = 24：每个顶点 6 个 float；offset:0/12 分别对应 @location(0) 位置与 @location(1) 颜色。
  • topology:'triangle-list' 表示每 3 个索引组成一个三角形；cullMode:'none' 关闭背面剔除，避免教学示例因顶点绕序丢失面。
  • depthStencil 开启深度测试：depthCompare:'less' 让更近的片段通过，depthWriteEnabled:true 写入深度，从而正确表现遮挡关系。

7. 深度纹理必须与画布同步

颜色附件来自 getCurrentTexture()，其尺寸随 canvas 绘图缓冲区变化；深度纹理必须与之完全一致。

因此 resizeCanvas() 后要按新尺寸重建 depthTexture。另外 GPUTexture 对象不暴露 width / height，本例用独立变量记录尺寸，避免每帧误判而反复销毁重建。

8. 命令编码与批处理

CommandEncoder → RenderPass → finish() → queue.submit() 构成一次绘制的提交链路。

  • 显式编码让驱动提前看到整帧工作，可做调度优化，并避免逐条调用带来的同步开销。
  • loadOp:'clear' 清空上一帧残留，storeOp:'store' 保留渲染结果。
  • requestAnimationFrame 让提交节奏与显示器刷新同步，避免画面撕裂。

9. 矩阵为什么用列主序

WGSL 与 WebGPU 约定列主序矩阵，mat4Multiply 中 a[i + k*4] 表示“第 k 列第 i 行”。

MVP 按 Projection × View × Model 相乘，顶点变换从右向左依次生效：模型旋转 → 相机变换 → 投影裁剪。顶点数组用 Float32Array，与 WGSL 的 f32 对齐，可被 GPU 直接读取。
