0. 为什么学 WebGPU

WebGPU 是新一代 Web 图形与计算 API，提供对现代 GPU 的低开销访问。

它解决了 WebGL 的什么问题？

维度WebGLWebGPU
抽象层次全局状态机，驱动隐式管理显式对象，开发者掌控状态
CPU 开销每次调用都做验证，开销高命令预编码批量提交，开销低
多线程受限原生支持 Worker 中编码命令
计算着色器需扩展一等公民（compute pipeline）
着色器语言GLSLWGSL（类型安全、可静态验证）
心智模型：把 WebGPU 想象成一条工厂流水线。你先把原料（顶点数据）放进仓库（Buffer），设计好图纸（Pipeline），写好工人指令（WGSL），然后把订单（CommandBuffer）一次性交给调度中心（Queue）执行。

本指南的学习路径

概念→ API 对象→ WGSL→ 管线→ 一帧渲染→ 旋转立方体

1. 核心概念

理解这些对象，就理解了 WebGPU 的骨架。

1.1 设备层次：Adapter → Device → Queue

对象作用为什么需要它
GPUAdapter代表一块物理 GPU（或软件回退）先探测硬件能力（features / limits），再决定怎么用
GPUDevice逻辑设备，所有资源的工厂资源隔离域，不同 Device 间资源不共享
GPUQueue命令队列批量提交命令，保证顺序，CPU 不必阻塞等待

1.2 资源对象

资源类比关键点
GPUBuffer线性内存块创建时必须声明 usage（VERTEX/INDEX/UNIFORM…），之后不可改
GPUTexture二维/三维图像用于颜色附件、深度附件、采样贴图
GPUSampler采样规则定义纹理过滤与寻址方式

1.3 绑定模型：Layout → BindGroup

WGSL 里的 @group(0) @binding(0) 是"插槽号"，GPUBindGroup 负责把真实的 Buffer/Texture 填进这些插槽。

这层间接设计让同一个管线可以切换不同资源——只需传入不同的 BindGroup，不必重建管线。

1.4 管线（Pipeline）

GPURenderPipeline 把着色器、顶点格式、图元拓扑、深度状态固化为一个不可变对象。创建时做严格验证（成本高），渲染时几乎零开销，所以只创建一次、每帧复用。

2. 一帧的生命周期

从 JS 数据到屏幕像素，一帧经过 8 个节点。

1 准备源数据→2 创建 Buffer→3 编译 WGSL→4 BindGroup→5 RenderPipeline→6 编码命令→7 提交队列→8 呈现画布

3. 初始化设备与上下文

所有 WebGPU 程序的第一步：拿设备、配画布。

4. WGSL 着色器

WGSL 是 WebGPU 的着色器语言，类型安全、可静态验证。

4.1 顶点着色器 vs 片段着色器

阶段输入输出职责
@vertex顶点属性、Uniform@builtin(position) 裁剪空间坐标把顶点放到屏幕正确位置
@fragment插值后的顶点输出@location(0) 颜色决定每个像素的颜色

4.2 本例的 WGSL 代码

            code: `
                struct Uniforms { mvp: mat4x4f };
                @group(0) @binding(0) var<uniform> uniforms: Uniforms;
                struct VertexOutput {
                    @builtin(position) position : vec4f,
                    @location(0) color : vec4f
                };
                @vertex
                fn vertex_main(@location(0) position : vec3f, @location(1) color : vec3f) -> VertexOutput {
                    var out: VertexOutput;
                    out.position = uniforms.mvp * vec4f(position, 1.0);
                    out.color = vec4f(color, 1.0);
                    return out;
                }
                @fragment
                fn fragment_main(input : VertexOutput) -> @location(0) vec4f {
                    return input.color;
                }
@location(0/1) 必须与 JS 侧 vertex.buffers.attributes 的 shaderLocation 一一对应；var<uniform> 是所有顶点共享的只读数据。

5. 渲染管线

管线把着色器与固定状态组装成一条绘制流水线。

关键状态解析

配置项本例值为什么
arrayStride6 * 4 = 24每个顶点 6 个 float（position 3 + color 3）
offset: 0 / 12对应 @location(0/1)颜色紧跟在位置之后
topologytriangle-list每 3 个索引组成一个三角形
cullModenone教学示例不因顶点绕序丢失面

6. 缓冲区与绑定

把 JS 数据上传为 GPU 资源，并建立着色器可见的绑定。

        const vertexBuffer = this.device.createBuffer({
            size: vertexData.byteLength,
            usage: gpuGlobal.GPUBufferUsage.VERTEX | gpuGlobal.GPUBufferUsage.COPY_DST,
            mappedAtCreation: true
        });
        new Float32Array(vertexBuffer.getMappedRange()).set(vertexData);
        vertexBuffer.unmap();

        const indexBuffer = this.device.createBuffer({
            size: indices.byteLength,
            usage: gpuGlobal.GPUBufferUsage.INDEX | gpuGlobal.GPUBufferUsage.COPY_DST,
            mappedAtCreation: true
        });
        new Uint16Array(indexBuffer.getMappedRange()).set(indices);
        indexBuffer.unmap();

        this.uniformBuffer = this.device.createBuffer({
            size: 64,
            usage: gpuGlobal.GPUBufferUsage.UNIFORM | gpuGlobal.GPUBufferUsage.COPY_DST
        });
        this.bindGroup = this.device.createBindGroup({
            layout: this.pipeline.getBindGroupLayout(0),
            entries: [{ binding: 0, resource: { buffer: this.uniformBuffer } }]
        });
常见坑：mappedAtCreation: true 只适合一次性上传静态数据；每帧变化的 MVP 矩阵用 queue.writeBuffer() 更新同一个 Buffer，不要每帧重建。

7. 3D 数学：MVP 矩阵

顶点从模型空间到屏幕，要依次经过 Model → View → Projection 变换。

模型空间×Model→ 世界空间×View→ 相机空间×Projection→ 裁剪空间

矩阵乘法在 TS 中写成 mat4Multiply(mat4Multiply(projection, view), model)，因为列主序下变换从右向左生效。

/** 矩阵乘法：a × b，列主序 */
function mat4Multiply(a: Mat4, b: Mat4): Mat4 {
    const out = new Float32Array(16);
    for (let c = 0; c < 4; c++) {
        for (let r = 0; r < 4; r++) {
            let sum = 0;
            for (let k = 0; k < 4; k++) sum += a[r + k * 4] * b[k + c * 4];
            out[r + c * 4] = sum;
        }
    }
    return out;
}

/** 绕 X 轴旋转 */
function mat4RotationX(angle: number): Mat4 {
    const c = Math.cos(angle), s = Math.sin(angle);
    return new Float32Array([1,0,0,0, 0,c,-s,0, 0,s,c,0, 0,0,0,1]);
}

/** 绕 Y 轴旋转 */
function mat4RotationY(angle: number): Mat4 {
    const c = Math.cos(angle), s = Math.sin(angle);
    return new Float32Array([c,0,s,0, 0,1,0,0, -s,0,c,0, 0,0,0,1]);
}

/** 透视投影：fovy 弧度、宽高比、近远平面 */
function mat4Perspective(fovy: number, aspect: number, near: number, far: number): Mat4 {
    const f = 1 / Math.tan(fovy / 2);
    return new Float32Array([
        f / aspect, 0, 0, 0,
        0, f, 0, 0,
        0, 0, (far + near) / (near - far), -1,
        0, 0, (2 * far * near) / (near - far), 0
    ]);
}
WGSL 与 WebGPU 约定列主序矩阵：a[i + k*4] 表示第 k 列第 i 行。用 Float32Array 存储可与 WGSL 的 f32 直接对齐。

8.2 类结构与渲染循环

WebGPURenderer 用 private 成员封装 device / pipeline / buffer 等状态，构造函数接收配置对象与状态回调。每帧流程：

resizeCanvas→ ensureDepthTexture→ 更新 MVP 矩阵→ writeBuffer→ 编码 RenderPass→ submit 
    /** 每帧：更新矩阵 → 编码命令 → 提交 */
    private render(): void {
        try {
            this.resizeCanvas();
            this.ensureDepthTexture();
            if (!this.depthTexture || !this.canvas.width || !this.canvas.height) {
                requestAnimationFrame(() => this.render());
                return;
            }
            this.rotation += 0.01;
            const aspect = this.canvas.width / this.canvas.height;
            const projection = mat4Perspective(this.fovY, aspect, this.near, this.far);
            const view = mat4LookAt([0,0,3], [0,0,0], [0,1,0]);
            const model = mat4Multiply(mat4RotationY(this.rotation), mat4RotationX(this.rotation * 0.6));
            const mvp = mat4Multiply(mat4Multiply(projection, view), model);
            this.device.queue.writeBuffer(this.uniformBuffer, 0, mvp);

            const encoder = this.device.createCommandEncoder();
            const pass = encoder.beginRenderPass({
                colorAttachments: [{
                    view: this.context.getCurrentTexture().createView(),
                    clearValue: { r: 0.05, g: 0.06, b: 0.09, a: 1 },
                    loadOp: 'clear',
                    storeOp: 'store'
                }],
                depthStencilAttachment: {
                    view: this.depthTexture.createView(),
                    depthClearValue: 1.0,
                    depthLoadOp: 'clear',
                    depthStoreOp: 'store'
                }
            });
            pass.setPipeline(this.pipeline);
            pass.setBindGroup(0, this.bindGroup);
            pass.setVertexBuffer(0, this.vertexBuffer);
            pass.setIndexBuffer(this.indexBuffer, 'uint16');
            pass.drawIndexed(this.indexCount);
            pass.end();
            this.device.queue.submit([encoder.finish()]);

            if (this.firstFrame.value) {
                this.firstFrame.value = false;
                this.onStatus('运行中：旋转立方体');
            }
            requestAnimationFrame(() => this.render());
        } catch (error) {
            this.onStatus('渲染错误：' + (error as Error).message);
        }
    }

9. Compute Shader：矩阵乘法

WebGPU 的计算管线是运行 AI 算法（CNN / Transformer）的基础。矩阵乘法是最小的内核示例。

9.1 为什么矩阵乘法重要

CNN 的卷积可展开为矩阵乘法，Transformer 的 Attention 与 FFN 本质也是矩阵乘加。GPU 擅长并行执行大量独立的乘加运算， compute shader 正是把这种并行性暴露给 Web 开发者。

AI 运算对应的 GPU 实现
全连接层 / Attention矩阵乘法（本例）
卷积层滑动窗口乘加，可用 texture 存权重
Softmax / LayerNorm逐行归约（reduction）+ 广播

9.2 Compute 管线 vs 渲染管线

对比项渲染管线Compute 管线
创建 APIcreateRenderPipelinecreateComputePipeline
着色器阶段vertex + fragment仅 @compute
调度方式drawIndexed()dispatchWorkgroups(x,y,z)
数据读写顶点/纹理var<storage> 读写缓冲

9.3 WGSL Compute Kernel

每个线程计算输出矩阵的一个元素；@builtin(global_invocation_id) 给出线程在网格中的坐标。

@group(0) @binding(0) var<storage, read> matrixA: array<f32>;
@group(0) @binding(1) var<storage, read> matrixB: array<f32>;
@group(0) @binding(2) var<storage, read_write> matrixC: array<f32>;

@compute @workgroup_size(1)
fn main(@builtin(global_invocation_id) gid: vec3u) {
    let row = gid.x;
    let col = gid.y;
    var sum = 0.0;
    for (var k = 0u; k < 4u; k = k + 1u) {
        sum = sum + matrixA[row * 4u + k] * matrixB[k * 4u + col];
    }
    matrixC[row * 4u + col] = sum;
}
@workgroup_size(1) 表示一个 workgroup 含 1 个线程；dispatchWorkgroups(4, 4, 1) 启动 4×4=16 个线程，正好覆盖 4×4 输出的每个元素。

9.4 TypeScript 侧：创建管线与调度

const shader = device.createShaderModule({ code: MATMUL_SHADER });
const pipeline = device.createComputePipeline({
    layout: 'auto',
    compute: { module: shader, entryPoint: 'main' }
});
// 三个 storage buffer：A、B 为只读输入，C 为可写输出
const bindGroup = device.createBindGroup({
    layout: pipeline.getBindGroupLayout(0),
    entries: [
        { binding: 0, resource: { buffer: bufferA } },
        { binding: 1, resource: { buffer: bufferB } },
        { binding: 2, resource: { buffer: bufferC } }
    ]
});
const encoder = device.createCommandEncoder();
const pass = encoder.beginComputePass();
pass.setPipeline(pipeline);
pass.setBindGroup(0, bindGroup);
pass.dispatchWorkgroups(4, 4, 1);
pass.end();
encoder.copyBufferToBuffer(bufferC, 0, staging, 0, 64);
device.queue.submit([encoder.finish()]);
await staging.mapAsync(GPUMapMode.READ);
const result = new Float32Array(staging.getMappedRange()).slice();

9.6 从示例到真实 AI 模型

本例只是 4×4 矩阵乘法。真实模型（如 MobileNet、Llama）会做三点升级：

  • 分块（tiling）：用 workgroup 共享内存缓存矩阵块，减少全局内存访问。
  • 量化：把 f32 权重转成 f16 或 int8，降低显存占用与带宽压力。
  • 算子融合：把矩阵乘 + 激活函数写进同一个 kernel，避免中间结果写回内存。
现成方案：tfjs-backend-webgpu、ONNX Runtime Web、WebLLM 都基于上述原理，可直接在浏览器跑 CNN 与小型 LLM 推理。

10. AI × WebGPU：从算子到模型

WebGPU 的计算管线让浏览器具备通用 GPU 计算能力，这是运行 AI 推理的关键。本章系统讲述 AI 与 WebGPU 的关系。

10.1 为什么在浏览器里跑 AI

优势说明

10.2 核心算子图谱：AI 模型由什么组成

再复杂的神经网络，拆到底都是少数几类运算的组合：

算子数学本质出现的网络WebGPU 实现
矩阵乘法（GEMM）C = A × B全连接层、Attention见 第 9 章

10.3 Compute 编程模型

理解三个概念就能写绝大部分 AI kernel：

概念含义类比
@compute 函数在每个线程上执行的 kernel一个工人
workgroup线程组，可共享 var<workgroup> 内存一个车间
dispatchWorkgroups(x,y,z)启动线程网格派出多少个车间
var<storage>GPU 可读写的全局缓冲区仓库里的原料与成品

线程的全局编号由 @builtin(global_invocation_id) 给出，AI kernel 通常用这个编号计算「我负责输出张量的哪个元素」。

10.4 实战：Softmax（Attention 的核心算子）

Softmax 需要处理一行数据：找最大值 → 求 exp 之和 → 归一化。直接对大数做 exp 会溢出，标准做法是先减最大值（数值稳定技巧）。

@compute @workgroup_size(1)
fn main(@builtin(global_invocation_id) gid: vec3u) {
    let row = gid.x;                    // 每个线程负责一行
    var maxVal = input[row * N];
    for (var i = 1u; i < N; i = i + 1u) {
        maxVal = max(maxVal, input[row * N + i]);
    }
    var sum = 0.0;
    for (var i = 0u; i < N; i = i + 1u) {
        sum = sum + exp(input[row * N + i] - maxVal);
    }
    for (var i = 0u; i < N; i = i + 1u) {
        output[row * N + i] = exp(input[row * N + i] - maxVal) / sum;
    }
}

10.5 从示例到真实模型：三大优化技术

技术原理收益
分块 Tiling把矩阵切成小块放进 var<workgroup> 共享内存，复用数据减少全局显存访问，GEMM 提速数倍
量化 Quantization权重从 f32 转 f16 / int8 / int4显存减半至 1/8，带宽压力骤降
算子融合 Fusion把 GEMM + 激活写进同一个 kernel避免中间张量写回显存

10.7 现实限制

  • 显存上限：maxStorageBufferBindingSize 通常 128MB~1GB，大模型权重放不下。
  • 精度支持：f16 需要 shader-f16 feature，并非所有设备支持。
  • 带宽瓶颈：Attention 是访存密集型，浏览器环境带宽不如原生 CUDA。
  • 只做推理：训练需要反向传播与海量显存，浏览器端不现实。
结论：CNN 推理（MobileNet、YOLO 小型版）完全可行；Transformer 推理建议 <1B 参数并量化到 4/8-bit；训练请在服务端做。
